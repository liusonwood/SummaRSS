# 🤖 SummaRss - RSS AI Daily Summarizer

This project is an automated RSS feed summarization tool powered by Python and OpenRouter (Gemini). It monitors multiple RSS sources, summarizes new entries from each source independently using AI, and publishes a new RSS feed containing separate summary items for each source.

## 🚀 Project Overview

- **Purpose**: To provide a condensed, AI-generated daily summary of RSS feeds to save time and reduce information overload.
- **Main Technologies**:
  - **Python 3**: Core processing logic using only standard libraries.
  - **OpenRouter API**: Integration with LLMs (defaulting to `google/gemini-2.0-flash-001`) for high-quality summarization.
  - **GitHub Actions**: Automation for daily execution and repository-based state persistence.
- **Architecture**:
  - **Multi-Source Support**: `RSS_SOURCE` accepts comma-separated URLs. Each source is processed independently with its own AI summary.
  - **State Management**: `DedupTracker` maintains per-source snapshots in `processed.txt`, atomically updating and avoiding infinite history file expansion. GitHub Actions persists this file using `actions/cache` (`runner.os-dedup-*`) to avoid committing state files to repository history.
  - **Incremental Workflow**: `fetch` -> `filter` -> `clean` -> `summarize` (per source) -> `publish` (combined).
  - **Git-as-DB**: The system commits the published `summary_feed.xml` back to the repository after each run, while dedup state is managed via Actions Cache.
  - **Error Isolation**: A single source failure does not affect processing of other sources.

## 🛠 Building and Running

### Prerequisites
- Python 3.x
- An OpenRouter API Key.

### Running Locally
To test the script locally, set the required environment variables and run:
```bash
export OPENROUTER_API_KEY="your_key_here"
export RSS_SOURCE="https://9to5mac.com/feed/,https://techcrunch.com/feed/"  # Multiple sources, comma-separated
export AI_MODEL="google/gemini-2.0-flash-001"
python3 summarize.py
```

### Automation
The project is configured to run automatically via GitHub Actions:
- **Schedule**: Daily at 07:35 UTC+8 (23:35 UTC).
- **Manual**: Can be triggered via the "Actions" tab in the GitHub repository.

## 📝 Key Files

- `summarize.py`: The main entry point containing logic for fetching, cleaning, DedupTracker deduplication, summarization, and XML generation.
- `.github/workflows/rss-summary.yml`: Defines the CI/CD pipeline for automated summarization.
- `processed.txt`: Persistent record of per-source processed URL content ID snapshots (`source_key\tcontent_id`).
- `summary_feed.xml`: The output RSS feed generated by the script.
- `example-rss-feed`: A sample RSS file used for demonstration or default processing.
- `README.md`: User-facing documentation and setup guide.
- `tests/test_summarize.py`: Test for summarize.py .Run/Add tests to make sure the code works.


## 📐 Development Conventions

- **Minimalism**: Favor Python standard libraries over third-party packages (e.g., `urllib.request` instead of `requests`).
- **Token Efficiency**: Always strip HTML and truncate content before sending it to the AI model.
- **Batching**: Summaries are generated by batching multiple items into a single prompt to save tokens and costs.
- **Security**: Never hardcode API keys; always use environment variables or GitHub Secrets.
- **Logical Comments**: Use "Why" comments to explain design decisions rather than "What" comments that repeat code logic.
